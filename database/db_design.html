💡 주요 설계 결정 노트

📸 faction 스냅샷 저장 (posts, comments)

사용자는 재테스트로 진영이 바뀔 수 있습니다. 게시물/댓글에 작성 당시의 진영을 별도 저장하지 않으면 이력이 왜곡됩니다. users.political_type과 무관하게 posts.faction으로 집계합니다.

🔢 비정규화 카운터 (vote_up_count 등)

게시물 목록 조회 시 매번 COUNT(*) 서브쿼리를 실행하면 대용량에서 느립니다. 추천/댓글 발생 시 이벤트로 카운터를 +1/-1 업데이트해 목록 조회는 단순 SELECT로 처리합니다.

◇ Polymorphic 관계 (votes, reports)

게시물과 댓글 모두 동일한 추천/신고 로직을 공유합니다. votable_type + votable_id 조합으로 두 테이블을 하나의 votes 테이블로 통합 관리합니다. Laravel의 morphTo 관계 활용.

📊 avg_score = raw ÷ active_user

진영 사용자 편중 문제를 방지합니다. active_user_count는 당일 게시물/댓글/투표 행위를 1회 이상 한 사용자만 카운트합니다. max(count, 1)로 0 나눔을 방지합니다.

🗂️ JSONB 활용 전략

political_tests.options(문항 보기), boards.config(게시판 설정), admin_action_logs.detail(변경 전후)에 JSONB를 적용합니다. GIN 인덱스를 걸어 내부 키 검색도 빠르게 처리합니다.

🗑️ Soft Delete 적용 범위

users, boards, posts, comments에 deleted_at 컬럼을 추가합니다. 삭제된 게시물의 댓글/신고 이력 보존, 관리자 복구 가능성, 법적 증거 보전을 위해 물리 삭제 대신 소프트 삭제를 사용합니다.
